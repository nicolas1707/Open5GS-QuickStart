# Configuração da Interface

## 1. Objetivo

Esta etapa documenta a preparação do cenário experimental de congestionamento em uma rede **5G Standalone (5G SA)** implementada com Open5GS e UERANSIM.

O objetivo é configurar três equipamentos de usuário (*User Equipment* — UEs) para utilizarem exclusivamente a mesma fatia lógica da rede, identificada como **eMBB (SST 1)** e associada à rede de dados `internet`.

Essa configuração permitirá avançar para os testes de tráfego concorrente, com o propósito de analisar o comportamento da rede quando múltiplos UEs compartilham a mesma fatia.

Nesta primeira etapa, o foco está no cadastro e na configuração dos assinantes por meio da WebUI do Open5GS.

---

## 2. Fundamentação Teórica

### 2.1. Compartilhamento da mesma fatia de rede

O *Network Slicing* permite organizar uma rede móvel em fatias lógicas destinadas a diferentes requisitos de serviço.

Neste experimento, os três UEs serão configurados para utilizar a mesma fatia:

| Parâmetro                  | Configuração |
| -------------------------- | ------------ |
| Tipo de fatia              | eMBB         |
| SST (*Slice/Service Type*) | `1`          |
| DNN (*Data Network Name*)  | `internet`   |
| Número de UEs              | `3`          |

O SST identifica o tipo de serviço associado à fatia, enquanto o DNN identifica a rede de dados à qual a sessão PDU deverá se conectar.

Ao configurar os três assinantes com o mesmo SST e DNN, estabelece-se a condição inicial para investigar o compartilhamento dos recursos da rede.

**Nota técnica:** o uso do mesmo SST e DNN não comprova, por si só, a existência de congestionamento nem estabelece um limite de banda compartilhado. Esses aspectos serão investigados posteriormente, durante os testes de tráfego concorrente.

### 2.2. Identificação e autenticação dos UEs

Cada UE deve possuir um IMSI distinto, utilizado para identificar o assinante no Core 5G.

Além do IMSI, o perfil do assinante contém parâmetros de autenticação, incluindo:

* **K (Subscriber Key):** chave secreta utilizada no processo de autenticação do assinante.
* **OPc (Operator Code):** parâmetro criptográfico utilizado no mecanismo de autenticação da rede móvel.

Neste laboratório, os três perfis utilizarão os mesmos valores de K e OPc para simplificar a configuração dos arquivos YAML do UERANSIM.

Essa reutilização é uma conveniência experimental e não representa uma prática recomendada para dispositivos reais, nos quais cada assinante deve possuir credenciais próprias.

## 3. Ambiente Utilizado

* **Sistema operacional:** Ubuntu 22.04 LTS
* **Core 5G:** Open5GS
* **Banco de dados:** MongoDB
* **Interface de gerenciamento:** Open5GS WebUI
* **Simulador de UE e RAN:** UERANSIM
* **Arquitetura:** 5G Standalone (SA)

O Core 5G e a WebUI devem estar instalados e operacionais antes do início deste procedimento.

## 4. Provisionamento dos Assinantes

### 4.1. Acesso à WebUI

A interface de gerenciamento do Open5GS pode ser acessada pelo navegador:

```text
http://localhost:9999
```

Utilize as credenciais configuradas durante a instalação. Na configuração padrão documentada pelo Open5GS:

* **Usuário:** `admin`
* **Senha:** `1423`

Caso a senha tenha sido alterada, utilize a credencial atual.

A WebUI permite cadastrar e editar os perfis dos assinantes, armazenados no banco de dados utilizado pelo Open5GS.

### 4.2. Configuração comum aos três UEs

Os três assinantes devem utilizar os seguintes parâmetros de autenticação e sessão:

| Campo                     | Valor                              |
| ------------------------- | ---------------------------------- |
| Subscriber Key (K)        | `8BAF473F2F8FD09487CCCBD7097C6862` |
| Operator Code (OPc)       | `E8ED3CA456BF83081672A61937F69302` |
| Tipo de chave de operador | `OPc`                              |
| SST                       | `1`                                |
| DNN/APN                   | `internet`                         |

Os valores de autenticação devem corresponder exatamente aos valores configurados nos respectivos arquivos YAML do UERANSIM. Divergências podem impedir a autenticação dos UEs.

### 4.3. UE 1

O primeiro assinante já existia no ambiente e estava inicialmente autorizado a utilizar três fatias distintas. Para adequá-lo ao cenário de congestionamento, seu perfil foi editado.

**Identificação do assinante:**

| Campo | Valor             |
| ----- | ----------------- |
| IMSI  | `999700000000001` |

**Procedimento realizado:**

1. Acessar a seção `Subscribers` na WebUI.
2. Localizar o assinante de IMSI `999700000000001`.
3. Clicar no ícone de edição.
4. Remover as configurações de sessão associadas ao SST 2 e ao SST 3.
5. Manter somente a configuração de sessão associada ao SST 1 e ao DNN `internet`.
6. Salvar as alterações.

Após a edição, o perfil do UE 1 deverá conter somente a configuração de sessão prevista para este cenário.

### 4.4. UE 2

Foi criado um novo assinante na WebUI com os seguintes parâmetros:

| Campo   | Valor             |
| ------- | ----------------- |
| IMSI    | `999700000000002` |
| SST     | `1`               |
| DNN/APN | `internet`        |

Os parâmetros K e OPc foram configurados conforme a seção 4.2.

Na seção de sessões e fatias, foi adicionada somente a configuração correspondente ao SST 1 e ao DNN `internet`.

Após o preenchimento, o cadastro foi salvo.

### 4.5. UE 3

Foi criado outro assinante na WebUI com os seguintes parâmetros:

| Campo   | Valor             |
| ------- | ----------------- |
| IMSI    | `999700000000003` |
| SST     | `1`               |
| DNN/APN | `internet`        |

Assim como nos outros perfis, foram utilizados os mesmos valores de K e OPc.

Na configuração de sessões e fatias, foi mantida somente a sessão correspondente ao SST 1 e ao DNN `internet`, removendo qualquer configuração de sessão associada às demais fatias, caso existente.

Após o preenchimento, o cadastro foi salvo.

## 5. Configuração Final Esperada

Ao concluir o provisionamento, os três assinantes deverão apresentar a seguinte configuração:

| UE   | IMSI              | SST | DNN        | Configuração de fatia |
| ---- | ----------------- | --: | ---------- | --------------------- |
| UE 1 | `999700000000001` |   1 | `internet` | Somente SST 1         |
| UE 2 | `999700000000002` |   1 | `internet` | Somente SST 1         |
| UE 3 | `999700000000003` |   1 | `internet` | Somente SST 1         |

Representação simplificada do cenário:

```text
                  Open5GS 5G Core
                         |
                  Slice eMBB (SST 1)
                    DNN: internet
                         |
             +-----------+-----------+
             |           |           |
            UE 1        UE 2        UE 3
             |           |           |
   IMSI 999700000000001  |           |
             IMSI 999700000000002   |
                         IMSI 999700000000003
```

Os três UEs possuem identidades distintas, mas compartilham a mesma configuração de fatia e rede de dados.
